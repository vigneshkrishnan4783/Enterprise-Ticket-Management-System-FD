Dynamic Priority Matrix & Smart Clocks

Severity is automatically computed from a 3×3 matrix of Business Impact × Service Urgency.

[Dynamic Matrix Calculation]
• High Impact + High Urgency ➔ CRITICAL PRIORITY (15m Response / 2h Resolution)
• High Impact + Medium Urgency ➔ HIGH PRIORITY (30m Response / 4h Resolution)
• Medium Impact + Medium Urgency ➔ MEDIUM PRIORITY (4h Response / 24h Resolution)
• Low Impact + Low Urgency ➔ LOW PRIORITY (8h Response / 72h Resolution)

Integration Architecture

Local Backend REST API Integration

Plugs straight into your local Spring Boot or Node.js server with live ping diagnostics.

REST API Endpoints:
• GET /health - Live connectivity probe
• GET /tickets - Filtered list with pagination and search
• POST /tickets - Ticket registration with dynamic priority matrix
• PUT /tickets/:id/status - Status transitions (Pending Customer, Resolve, Reopen)
• PUT /tickets/:id/assign - Team & Agent assignment with justification
• POST /tickets/:id/comments - Public replies & private internal notes
• POST /tickets/:id/feedback - Customer satisfaction (CSAT) rating

Default Target: http://localhost:8080/api (Automatic Mock DB fallback when offline)
